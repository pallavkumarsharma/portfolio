Real-Time Clinical Integration for Arkos Health

Architecting an end-to-end HL7 event ingestion platform on MuleSoft CloudHub — connecting Salesforce Health Cloud with enterprise EHR systems while maintaining full HIPAA compliance across all PHI data flows.

The challenge

Arkos Health needed to bridge a significant gap between their Salesforce Health Cloud environment and an upstream EHR system generating HL7 v2 event streams. Clinical alerts — the kind of real-time notifications that affect patient care decisions — were being processed manually, with delays. The integration needed to be reliable, fast, and HIPAA-compliant from day one.

The added complexity: HL7 v2 messages from the EHR were inconsistently encoded, with no schema enforcement at the source. Every message had to be treated as potentially malformed at the ingestion layer.

Architecture

I architected a three-tier API-led integration on MuleSoft CloudHub:

  • System API — HL7 v2 ingestion, validation, and normalisation. Untrusted input in; clean, validated FHIR-aligned objects out. This layer absorbed all the messiness of the upstream source.
  • Process API — clinical alert routing logic, patient case matching, and workflow orchestration. This layer understood the business rules; the system layer didn't need to.
  • Experience API — Salesforce Health Cloud integration, exposing the data contract that Salesforce consumed. Built to match Salesforce's data model, not the EHR's.

All PHI traversing the integration was encrypted in transit (TLS 1.2+), with payload masking policies applied at the gateway layer for logging. Audit events were written to a structured log store on every API call involving PHI.

Outcomes

Clinical alert processing moved from a manual, delayed workflow to a real-time automated pipeline. Patient case management records in Salesforce Health Cloud are now populated automatically when clinical events occur upstream.

The most important quality metric wasn't throughput — it was zero PHI leakage events. The security architecture held under load testing and in production.

HIPAA compliance approach

HIPAA compliance wasn't a feature we added at the end — it was built into the architecture from the design phase. Key decisions: access control at the API gateway (OAuth 2.0 scopes scoped to specific PHI resource types), audit logging at every integration layer, and a data minimisation policy that stripped PHI from any payload that didn't require it downstream.
